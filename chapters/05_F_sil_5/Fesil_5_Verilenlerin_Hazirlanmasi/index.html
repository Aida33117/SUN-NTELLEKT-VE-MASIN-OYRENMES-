5.1. Verilənlərin hazırlanmasının maşın öyrənməsində rolu

Verilənlərin hazırlanması (data preparation / preprocessing) xam məlumatı seçilmiş alqoritmin qəbul edə biləcəyi formaya gətirən mərhələlər toplusudur. Bu mərhələ yalnız texniki təmizləmə deyil; ölçmə vahidlərinin uyğunlaşdırılması, kateqoriyaların semantik mənasının saxlanması, təlim və testin ayrılması, qərəz və sızma risklərinin idarə olunmasını da əhatə edir.

Çirkli və uyğunsuz verilənlər modelə təsadüfi səs-küy, sistematik qərəz və yanlış əlaqələr öyrədə bilər. Məsələn, gəlir sütununda AZN və USD qarışdırılıbsa, modelin hesabladığı məsafələr və statistik göstəricilər mənasız ola bilər.

Keyfiyyət

Dəqiqlik, tamlıq, ardıcıllıq və etibarlılıq.

Uyğunluq

Modelin gözlədiyi tip, forma və miqyas.

Təkrarlana bilmə

Eyni qaydaların yeni məlumatlara tətbiqi.

Vacib fərq: preprocessing bütün problemləri “silərək” həll etmək deyil. Məlumatın mənasını qoruyaraq, sənədləşdirilmiş və əsaslandırılmış transformasiya aparmaqdır.

5.2. Verilənlərin təmizlənməsi

Verilənlərin təmizlənməsi (data cleaning) səhv, ziddiyyətli, təkrarlanan, formatı pozulmuş və ya domen qaydalarına uyğun olmayan qeydlərin aşkarlanması və idarə edilməsidir. Təmizləməyə başlamazdan əvvəl orijinal datasetin dəyişməz nüsxəsini saxlayın və bütün düzəlişləri qeydə alın.

Tipik yoxlama istiqamətləri

  • Tip və format: tarix sütununun mətn kimi oxunması, rəqəmdə vergül/nöqtə fərqi.
  • Aralıq yoxlaması: yaşın mənfi, davamiyyətin 100%-dən böyük olması.
  • Standartlaşdırma: “Bakı”, “baki”, “BAKI” kimi kateqoriya yazılışları.
  • Təkrar qeydlər: eyni ID və tarix kombinasiyasının təkrarlanması.
  • Domen məntiqi: bitmə tarixi başlanğıc tarixindən əvvəl ola bilməz.

df.columns = (df.columns.str.strip()

              .str.replace(" ", "_"))
df = df.drop_duplicates()
df["date"] = pd.to_datetime(df["date"], errors="coerce")

5.3. Çatışmayan qiymətlərin aşkarlanması və doldurulması

Çatışmayan qiymətlərin emalı dəyişənin tipinə, çatışmazlığın səbəbinə və paylanmasına əsaslanmalıdır. Ədədi sütunda orta qiymət kənar müşahidələrdən təsirlənir; median çox vaxt daha dayanıqlı seçimdir. Kateqorik sütunda ən çox rast gəlinən sinif və ya ayrıca “Naməlum” kateqoriyası istifadə oluna bilər. Lakin heç bir doldurma üsulu avtomatik olaraq düzgün deyil.

5.4. Kənar qiymətlərin müəyyənləşdirilməsi

Kənar qiymətlər (outliers) paylanmanın əsas hissəsindən fərqlənən müşahidələrdir. Onlar giriş xətası, cihaz nasazlığı, nadir, lakin real hadisə və ya fərqli alt-populyasiya göstəricisi ola bilər. Əvvəlki fəsildə öyrənilən IQR üsulu ilkin aşkarlama üçün yararlıdır; qərar kontekstlə verilməlidir.

\[IQR=Q_3-Q_1,\quad L=Q_1-1.5IQR,\quad U=Q_3+1.5IQR\]

Əgər \(x<L\) və ya \(x>U\) olarsa, müşahidə IQR qaydasına görə potensial kənar qiymət kimi işarələnir.

Outlier-lə işləmə variantları

  • mənbəyə qayıdıb səhvi düzəltmək;
  • müşahidəni saxlamaq və robust model/metric seçmək;
  • əsaslandırılmış winsorization və ya clipping tətbiq etmək;
  • log və ya başqa transformasiya ilə çəp paylanmanı azaltmaq;
  • yalnız ölçmə xətası təsdiqləndikdə silmək.
Python · IQR ilə namizəd outlier-lər
q1 = df["income"].quantile(0.25)
q3 = df["income"].quantile(0.75)
iqr = q3 - q1
lower, upper = q1 - 1.5*iqr, q3 + 1.5*iqr

outlier_mask = (df["income"] < lower) | (df["income"] > upper)
print(df.loc[outlier_mask, "income"])
Düyməni seçin.

5.5. Kateqorik dəyişənlərin kodlaşdırılması

Bir çox ML alqoritmi girişdə ədədi matris gözləyir. Mətn kateqoriyalarının rəqəmə çevrilməsi kodlaşdırma (encoding) adlanır. Kodlar kateqoriyanın mənasını və sırasını təhrif etməməlidir.

Nominal dəyişənlərdə təbii sıra yoxdur (məsələn, şəhər və rəng). Ordinal dəyişənlərdə isə sıralama var (aşağı, orta, yüksək). Bu fərq kodlaşdırma üsulunun seçilməsini müəyyən edir.

Nominal

“Bakı”, “Gəncə”, “Şəki”

Adətən One-Hot Encoding uyğundur.

Ordinal

“Aşağı”, “Orta”, “Yüksək”

Əsaslandırılmış sıra ilə ordinal encoding istifadə oluna bilər.

Yanlış yanaşma nümunəsi: şəhərlərə Bakı=1, Gəncə=2, Şəki=3 kodu vermək bəzi alqoritmlərdə Şəkinin “Bakıdan üç dəfə böyük” və ya arada məsafə olduğu təəssüratını yarada bilər. Nominal dəyişən üçün belə rəqəmsal sıra mənalı deyil.

5.6. Label Encoding və One-Hot Encoding

Label Encoding kateqoriyaları tam ədədlərlə əvəz edir. Bu üsul çox vaxt hədəf etiketlərinin kodlaşdırılması üçün uyğundur. Giriş xüsusiyyətində istifadə ediləndə süni sıralama yarada bilər. Ordinal Encoding yalnız həqiqi sıra mövcud olduqda və sıra açıq müəyyənləşdirildikdə istifadə edilməlidir.

One-Hot Encoding hər kateqoriya üçün ayrıca ikili sütun yaradır. Məsələn, “rəng” = {qırmızı, yaşıl, mavi} dəyişəni üç indikator sütununa çevrilir. Bəzi xətti modellərdə intercept ilə birlikdə tam kollinearılığın qarşısını almaq üçün bir sütun buraxıla bilər (`drop="first"`); bu seçim model və interpretasiya tələbindən asılıdır.

5.7. Normallaşdırma və standardlaşdırma

Ədədi xüsusiyyətlər fərqli miqyaslarda olduqda məsafə və gradient əsaslı alqoritmlər bir dəyişənə həddindən artıq həssas ola bilər. Məsələn, yaş 18–70, illik gəlir isə 5 000–100 000 aralığında ola bilər. Scaling dəyişənləri müqayisə edilə bilən miqyasa gətirir.

Normallaşdırma termini kontekstdən asılı olaraq müxtəlif miqyaslandırma üsullarını ifadə edə bilər. Bu fəsildə əsasən Min-Max Scaling nəzərdə tutulur. Standardlaşdırma isə orta qiyməti 0, standart kənarlaşması 1 olan z-score çevrilməsidir.

Scaling faydalı ola bilər

KNN, K-means, SVM, PCA, gradient əsaslı neyron şəbəkələri və regularizasiya tətbiq edən modellər.

Həmişə vacib deyil

Qərar ağacları və bir çox tree ensemble modelləri miqyas fərqinə adətən həssas deyil.

Scaling yalnız təlim məlumatında fit edilməlidir. Test və real tətbiq məlumatı həmin train-dən öyrənilmiş parametr ilə transformasiya olunur.

5.8. Min-Max Scaling və StandardScaler

Min-Max Scaling verilənləri adətən \([0,1]\) intervalına çevirir:

\[x' = \frac{x-x_{\\min}}{x_{\\max}-x_{\\min}}\]

StandardScaler z-score çevrilməsini tətbiq edir:

\[z = \frac{x-\mu}{\sigma}\]

Burada \(\mu\) təlim nümunəsinin orta qiyməti, \(\sigma\) isə standart kənarlaşmasıdır. StandardScaler nəticəsinin hər qiyməti mütləq [-1,1] aralığında olmur. Min-Max outlier-lərdən təsirlənə bilər; StandardScaler də outlier-lərə həssasdır. Belə hallarda RobustScaler kimi alternativlər nəzərdən keçirilə bilər.

5.10. Ölçülərin azaldılması və PCA

Ölçülərin azaldılması (dimensionality reduction) çoxsaylı xüsusiyyətləri daha az ölçülü təqdimata çevirməklə məlumatın əsas strukturunu qorumağa çalışır. PCA (Principal Component Analysis) verilənlərdə mümkün qədər çox dispersiyanı izah edən, bir-birinə ortoqonal istiqamətlər – əsas komponentlər yaradır.

PCA adətən ədədi və miqyaslandırılmış xüsusiyyətlər üzərində tətbiq edilir. Komponentlər ilkin dəyişənlərin xətti kombinasiyalarıdır; buna görə interpretasiya çətinləşə bilər. PCA nəzarətsiz üsuldur və hədəf dəyişənini birbaşa nəzərə almır.

Şəkil 5.3. İki ölçülü veriləndə əsas dəyişkənlik istiqamətinin (PC1) konseptual təsviri.
\[Z = XW\]

Burada \(X\) (mərkəzləşdirilmiş və lazım olduqda miqyaslandırılmış) verilənlər matrisi, \(W\) seçilmiş əsas komponentlərin istiqamət vektorları, \(Z\) isə aşağı ölçülü təqdimatdır.

Python · PCA və izah olunan dispersiya
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_s = scaler.fit_transform(X_train)
X_test_s = scaler.transform(X_test)

pca = PCA(n_components=0.95)
X_train_pca = pca.fit_transform(X_train_s)
X_test_pca = pca.transform(X_test_s)

print(pca.n_components_)
print(pca.explained_variance_ratio_.sum())
Düyməni seçin.

5.12. Data Leakage problemi və qarşısının alınması

Data leakage modelin təlimi və ya model seçimi zamanı real proqnoz anında əlçatan olmayacaq məlumatın prosesə daxil olmasıdır. Bu, qiymətləndirmə nəticəsini süni şəkildə yüksəldə və real istifadədə zəif performansa səbəb ola bilər.

Əsas sızma növləri

  • Preprocessing leakage: scaling/imputation parametrlərinin train+test birlikdə hesablanması.
  • Target leakage: hədəfi birbaşa və ya dolayı açıqlayan feature-in girişə daxil edilməsi.
  • Temporal leakage: gələcəkdə yaranan məlumatın keçmiş hadisəni proqnozlaşdırmaq üçün istifadəsi.
  • Group leakage: eyni şəxsə/obyektə aid qeydlərin train və test arasında bölünməsi.
Səhv

Əvvəl bütün datasetə fit

scaler.fit(X)
X_scaled = scaler.transform(X)
X_train, X_test = split(X_scaled)

Test məlumatının statistikası scaling parametrinə təsir edir.

Düzgün

Əvvəl split, sonra fit

X_train, X_test = split(X)
scaler.fit(X_train)
X_train_s = scaler.transform(X_train)
X_test_s = scaler.transform(X_test)

Test hissəsi transformasiya parametrinin öyrənilməsində iştirak etmir.

Qızıl qayda: Test dəstinə yalnız yekun qiymətləndirmə üçün müraciət edin. Hər dəfə test nəticəsinə baxaraq model qərarlarını dəyişmək test dəstini faktiki validation dəstinə çevirir.

5.13. Verilənlərin hazırlanması üçün Pipeline mexanizmi

Scikit-learn Pipeline preprocessing addımlarını və modeli vahid obyekt daxilində birləşdirir. ColumnTransformer isə ədədi və kateqorik sütunlara fərqli transformasiyalar tətbiq etməyə imkan verir. Pipeline cross-validation və hiperparametr axtarışında transformasiyaların hər fold-un train hissəsində fit edilməsini təmin etməyə kömək edir.

Şəkil 5.5. Ədədi və kateqorik sütunlar üçün ColumnTransformer və Pipeline arxitekturası.
Tam nümunə · ColumnTransformer + Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import RandomForestClassifier

numeric_features = ["age", "income"]
categorical_features = ["city", "education"]

numeric_pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler())
])

categorical_pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore"))
])

preprocessor = ColumnTransformer([
    ("num", numeric_pipe, numeric_features),
    ("cat", categorical_pipe, categorical_features)
])

model = Pipeline([
    ("preprocess", preprocessor),
    ("classifier", RandomForestClassifier(random_state=42))
])

model.fit(X_train, y_train)
predictions = model.predict(X_test)
Düyməni seçin.
Qeyd: nümunədəki sütun adları və model seçimi datasetə uyğun dəyişdirilməlidir. Real layihədə target sütunu X-dən çıxarılmalı, split Pipeline-dan əvvəl aparılmalı və uyğun cross-validation strategiyası seçilməlidir.

İşlək kod skeleti

import pandas as pd
import numpy as np

from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import classification_report, accuracy_score

# 1. CSV faylını yükləyin; yolunuzu uyğunlaşdırın
df = pd.read_csv("adult.csv", na_values=["?", " ?"])

# 2. Sütun adlarını təmizləyin
df.columns = df.columns.str.strip()

# 3. Təkrarlanan qeydləri yoxlayın və çıxarın
print("Duplicates:", df.duplicated().sum())
df = df.drop_duplicates().copy()

# 4. Hədəf sütununu müəyyən edin (datasetə uyğunlaşdırın)
target = "income"
df[target] = df[target].astype(str).str.strip()
X = df.drop(columns=[target])
y = df[target]

# 5. Sütun qrupları
numeric_features = X.select_dtypes(include=["number"]).columns.tolist()
categorical_features = X.select_dtypes(
    include=["object", "category", "bool"]
).columns.tolist()

# 6. Train/test split — preprocessing-dən əvvəl
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42, stratify=y
)

# 7. Ədədi və kateqorik emal axınları
numeric_pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler())
])
categorical_pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore"))
])

preprocessor = ColumnTransformer([
    ("num", numeric_pipe, numeric_features),
    ("cat", categorical_pipe, categorical_features)
])

# 8. Preprocessing + model vahid Pipeline-da
pipe = Pipeline([
    ("preprocess", preprocessor),
    ("model", HistGradientBoostingClassifier(
        random_state=42
    ))
])

pipe.fit(X_train, y_train)
pred = pipe.predict(X_test)

print("Accuracy:", accuracy_score(y_test, pred))
print(classification_report(y_test, pred))
Texniki uyğunluq qeydi: yuxarıdakı nümunədə OneHotEncoder seyrək (sparse) matris yarada bilər, HistGradientBoostingClassifier isə versiyadan asılı olaraq sparse giriş qəbul etməyə bilər. İcra zamanı belə uyğunsuzluq yaranarsa, `OneHotEncoder(handle_unknown="ignore", sparse_output=False)` (köhnə Scikit-learn-də `sparse=False`) istifadə edin və ya sparse matris qəbul edən uyğun təsnifatçı seçin. Bu qeyd kitabxana versiyası fərqlərini nəzərə almaq üçündür.
