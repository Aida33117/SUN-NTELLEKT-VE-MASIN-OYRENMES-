16.1. Süni intellektdə izaholunma problemi

16.2. Explainable AI (XAI) anlayışı

Explainable AI (XAI) süni intellekt modelinin proqnozlarını və davranışını insan üçün anlaşılan formada açıqlamağa yönəlmiş metodlar, alətlər və dizayn prinsipləri toplusudur. XAI-nin məqsədi yalnız “nəticə budur” demək deyil, nəticənin hansı xüsusiyyətlərdən və hansı məntiqdən yarandığını göstərməkdir.

İzahın iki əsas yanaşması

Intrinsic interpretability

Modelin quruluşu özlüyündə anlaşılandır: xətti model, kiçik qərar ağacı, qayda əsaslı sistem.

Post-hoc explainability

Əvvəl öyrədilmiş mürəkkəb modelin qərarı sonradan ayrıca metodla izah edilir: SHAP, LIME, saliency.

Model qərarının izahı istifadə olunan tapşırığa, auditoriyaya və qərarın riskinə uyğun olmalıdır. Məsələn, data scientist üçün SHAP qrafiki faydalıdır; tələbə üçün isə “davamiyyətiniz aşağı olduğuna görə risk göstəricisi yüksəlib” kimi aydın, kontekstli izah daha anlaşıqlı ola bilər.

Əgər β₁ müsbətdirsə, digər dəyişənlər sabit saxlanıldıqda x₁ artımı proqnozun artması ilə əlaqəlidir. Bu, səbəb-nəticə əlaqəsini sübut etmir; yalnız modelin öyrəndiyi statistik əlaqəni göstərir.

İzah olunan akademik risk nümunəsi

16.4. Feature Importance

Feature Importance modelin proqnozlarında giriş xüsusiyyətlərinin nisbi əhəmiyyətini qiymətləndirir. “Feature” modelə verilən dəyişəndir: davamiyyət, imtahan balı, yaş, müraciət sayı, sensor temperaturu və s. Əhəmiyyət göstəricisi xüsusiyyətin model üçün nə dərəcədə faydalı olduğunu ifadə edir, lakin təsirin səbəbini və istiqamətini təkbaşına açıqlamır.

Əsas yanaşmalar

MetodNecə hesablanır?Üstünlük / məhdudiyyət
Tree impurity importanceAğac düyünlərində qeyri-müəyyənliyin azalması cəmlənirSürətlidir; yüksək kardinaliteli feature-lərə üstünlük verə bilər
Permutation importanceBir feature qarışdırılır, model performansının azalması ölçülürModeldən asılı deyil; əlaqəli feature-lər nəticəni qarışdıra bilər
Coefficient magnitudeStandartlaşdırılmış xətti model əmsallarının ölçüsü müqayisə edilirXətti fərziyyəyə və miqyaslandırmaya həssasdır
Importanceⱼ ≈ Score(original) − Score(permutedⱼ)

Permutation importance-də göstərici qarışdırıldıqdan sonra modelin keyfiyyəti nə qədər azalırsa, həmin feature modelin proqnozu üçün bir o qədər əhəmiyyətli ola bilər.

İnteraktiv feature importance cədvəli

Aşağıdakı faizlər nümunə modelin tədris məqsədli göstəriciləridir; real eksperiment nəticəsi deyil.

Davamiyyət nümunədə ən yüksək əhəmiyyətə malikdir. Bu, səbəb-nəticə demək deyil.
Əlaqəli dəyişənlər: davamiyyət və LMS-ə giriş sayı bir-biri ilə güclü əlaqəli ola bilər. Model əhəmiyyəti bu iki feature arasında bölüşdürə bilər. Buna görə tək bir sıralamaya əsasən elmi nəticə çıxarmaq olmaz.

16.5. SHAP və LIME metodlarına giriş

SHAP və LIME mürəkkəb modelin konkret proqnozunu izah etmək üçün istifadə edilən post-hoc metodlardır. Hər ikisi lokal izah yarada bilər, lakin fərqli prinsipə əsaslanır.

SHAP — SHapley Additive exPlanations

Kooperativ oyunlar nəzəriyyəsindəki Shapley dəyərlərindən istifadə edərək hər feature-in proqnoza töhfəsini paylayır. Töhfənin müsbət və ya mənfi istiqamətini göstərə bilər.

LIME — Local Interpretable Model-agnostic Explanations

Seçilmiş müşahidənin ətrafında nümunələr yaradır, mürəkkəb modelin lokal davranışına sadə, şərh edilən model uyğunlaşdırır.

SHAP-ın əsas ideyası

f(x) = φ₀ + Σᵢ φᵢ

φ₀ baza proqnozu, φᵢ isə i-ci feature-in həmin müşahidə üçün töhfəsidir. Təsnifatda izah çox vaxt modelin ehtimalı deyil, xam model çıxışı (məsələn, log-odds) üzərində qurula bilər; qrafikin hansı miqyasda olduğunu yoxlamaq vacibdir.

φᵢ = ΣS⊆F\\{i} [ |S|!(M−|S|−1)! / M! ] · [ f(S∪{i}) − f(S) ]

Burada F bütün feature-lər çoxluğu, M feature sayı, S isə i feature-i daxil etməyən alt çoxluqdur. Düstur i feature-in bütün mümkün iştirak sıralamalarında orta marjinal töhfəsini hesablayır.

LIME-in əsas ideyası

ξ(x) = arg ming∈G L(f,g,πₓ) + Ω(g)

f — izah edilən mürəkkəb model, g — sadə lokal izah modeli, πₓ — x müşahidəsinə yaxın nümunələrə daha çox çəki verən yaxınlıq funksiyası, Ω(g) isə izah modelinin mürəkkəbliyini cərimələyən termindir.

Şəkil 16.3. SHAP feature töhfələrini paylayır; LIME seçilmiş nümunənin ətrafında lokal izah modeli qurur.

SHAP və LIME müqayisəsi

MeyarSHAPLIME

İzahFeature töhfələrinin cəmiYaxınlıq bölgəsində sadə model
ÜstünlükNəzəri əsaslandırma və additiv izahModel-agnostic, konseptual cəhətdən çevik
MəhdudiyyətBəzi modellərdə hesablama bahalıdır; fon paylanması vacibdirNümunələmə və yaxınlıq parametrinə həssas ola bilər

İnteraktiv SHAP tipli töhfə izahı

Bu kalkulyator Shapley hesablamasını deyil, additiv izah məntiqini nümayiş etdirir. Dəyərlər tədris nümunəsidir.

Yekun proqnoz burada görünəcək.

16.7. Modelin ədalətliliyi (Fairness)

Fairness modelin müxtəlif insan qruplarına təsirini qiymətləndirmək və əsassız, zərərli fərqləri aşkar etmək üçün istifadə olunan prinsiplər və metriklər toplusudur. Ədalətliliyin vahid, bütün hallara uyğun tərifi yoxdur: seçilən meyar hüquqi, sosial və tətbiq kontekstindən asılıdır.

İnteraktiv qrup müqayisəsi

İki qrup üçün hipotetik qərar göstəricilərini daxil edin. Bunlar real əhali və ya universitet statistikası deyil.

Fərq burada göstəriləcək.

Ədalətlilik kompromisləri

Fərqli fairness meyarları bəzi hallarda eyni anda təmin edilə bilməz. Xüsusilə qrupların baza riskləri fərqli olduqda calibration və error-rate parity kimi şərtlər arasında riyazi kompromislər yarana bilər. Buna görə metrik seçimi yalnız texniki deyil, normativ və hüquqi qərardır.

16.8. Məxfilik və informasiya təhlükəsizliyi

AI sistemləri şəxsi məlumatlar, mətnlər, şəkillər, səs yazıları və davranış tarixçəsi ilə işləyə bilər. Məxfilik fərdin məlumatına necə nəzarət etməsi ilə, informasiya təhlükəsizliyi isə məlumatın məxfiliyinin, bütövlüyünün və əlçatanlığının qorunması ilə bağlıdır.

Məlumatın qorunması prinsipləri

  • Data minimization: məqsəd üçün zəruri olan minimum məlumatı toplamaq.
  • Pseudonymization və anonymization: identifikatorları ayırmaq və mümkün olduqda şəxsi tanımanı aradan qaldırmaq.
  • Encryption: ötürülmə və saxlanma zamanı şifrələmə.
  • Access control: yalnız səlahiyyətli şəxslərə giriş vermək.
  • Retention policy: məlumatı müəyyən edilmiş müddətdən artıq saxlamamaq.
  • Audit log: kim, nə vaxt, hansı məlumatdan istifadə edib — izləmək.

Differential Privacy ideyası

Differential Privacy (DP) fərdi şəxsin məlumatının dataset-ə daxil olmasının nəticəyə təsirini məhdudlaşdıran riyazi məxfilik təminatıdır. Əsas intuitiv parametr ε (epsilon) məxfilik büdcəsini ifadə edir: digər şərtlər eyni olduqda ε kiçildikcə daha güclü məxfilik təminatı əldə edilir, lakin faydalılıq azala bilər.

Pr[M(D) ∈ S] ≤ eε · Pr[M(D′) ∈ S] + δ

D və D′ bir fərdin məlumatı ilə fərqlənən qonşu dataset-lər, M mexanizm, S mümkün çıxışlar çoxluğudur. ε və δ məxfilik zəmanətinin parametrləridir.

Praktik qeyd: “Məlumatı anonimləşdirdik” demək avtomatik təhlükəsizlik zəmanəti deyil. Xarici məlumatlarla birləşdirmə yenidən identifikasiya riski yarada bilər.

16.9. Süni intellektdə etik prinsiplər

Etika texniki cəhətdən mümkün olan hər qərarın tətbiq edilməli olmadığını xatırladır. AI sisteminin məqsədi, istifadəçilərə və cəmiyyətə təsiri, səhvlərin kimə zərər verə biləcəyi layihənin əvvəlindən qiymətləndirilməlidir.

İnsan mərkəzlilik

İnsan hüquqları, ləyaqət və seçim azadlığı qorunmalıdır.

Ədalətlilik

Qərəz və ayrı-seçkilik riskləri araşdırılmalıdır.

Şəffaflıq

İstifadəçiyə AI ilə qarşılıqlı əlaqə və qərar məntiqi barədə uyğun məlumat verilməlidir.

Hesabatlılıq

Sistemə görə məsuliyyət daşıyan şəxslər və proseslər müəyyən edilməlidir.

Məxfilik

Şəxsi məlumatlar məqsədəuyğun və təhlükəsiz işlənməlidir.

Təhlükəsizlik

Sistem gözlənilməz hallara, hücumlara və nasazlıqlara qarşı yoxlanmalıdır.

Etik təsirin qiymətləndirilməsi

  1. Problemi və AI istifadəsinin zəruriliyini müəyyənləşdirin.
  2. Təsirə məruz qalan tərəfləri və həssas qrupları müəyyən edin.
  3. Fayda, zərər, qərəz, məxfilik və təhlükəsizlik risklərini qiymətləndirin.
  4. Riskin azaldılması tədbirlərini və insan nəzarətini layihələndirin.
  5. İstifadə zamanı monitorinq, şikayət və düzəliş mexanizmi yaradın.
Universitet nümunəsi: AI tələbəyə akademik dəstək ehtiyacını müəyyənləşdirə bilər, lakin təqaüd, qəbul və ya intizam qərarını izahsız və avtomatik verməməlidir. Tələbənin məlumatı düzəltmək, nəticəyə etiraz etmək və insan tərəfindən baxılmasını tələb etmək imkanı olmalıdır.

  2. Mənbələri yoxlamaq: generativ modelin təqdim etdiyi məqalə, DOI, qanun, statistika və istinadlar orijinal mənbədə yoxlanılmalıdır. Modelin uydurduğu istinad elmi mənbə sayılmır.

  7. İnsan nəzarəti: yüksək təsirli qərarlarda AI nəticəsi qərar verən şəxsin müstəqil qiymətləndirməsini əvəz etməməlidir.

16.11.5. ISO/IEC 42001:2023 — AI idarəetmə sisteminin qurulması

ISO/IEC 42001:2023 təşkilatın AI sistemlərini məsuliyyətli şəkildə təmin etməsi və ya istifadə etməsi üçün idarəetmə sistemi tələblərini müəyyən edir. Bu standart yalnız proqramçıya aid deyil: rəhbərlik, hüquq, informasiya təhlükəsizliyi, data komandası, satınalma, insan resursları və istifadəçi bölmələri də AI idarəetməsində rol alır.

Universitetdə tətbiq nümunəsi

Tutaq ki, universitet tələbələrin akademik dəstək ehtiyacını proqnozlaşdıran model tətbiq edir. ISO/IEC 42001 yanaşması ilə aşağıdakı idarəetmə mexanizmləri qurula bilər:

  1. Rəhbərlik AI siyasətini təsdiq edir və sistemin məqsədini “dəstəyə ehtiyacı olan tələbələri erkən müəyyənləşdirmək” kimi məhdudlaşdırır.
  2. AI sisteminin sahibi, məlumatların sahibi, texniki operator, etik nəzarətçi və qərar verən akademik əməkdaş müəyyən edilir.
  3. Modelin istifadə edilə biləcəyi və istifadə edilməməli olduğu hallar sənədləşdirilir. Məsələn, model təkbaşına tələbənin xaric edilməsi və ya təqaüdünün dayandırılması üçün istifadə edilmir.
  4. Verilənlərin mənbəyi, keyfiyyəti, hüquqi əsasları və saxlanma müddəti qeydə alınır.
  5. Model test edilir, müxtəlif qruplar üzrə nəticələr yoxlanılır, insan nəzarəti və şikayət mexanizmi qurulur.
  6. İstismarda performans, data drift, insidentlər və istifadəçi şikayətləri monitorinq edilir.
  7. Audit nəticələrinə əsasən siyasət, proses və model yenilənir.
Nəticə: ISO/IEC 42001 yanaşması “model yaratdıq və işə saldıq” mərhələsində bitmir. Təşkilat AI-nin məqsədəuyğunluğunu, risklərini, cavabdehləri və davamlı nəzarətini idarə edir. ISO-nun rəsmi səhifəsi.

16.11.6. ISO/IEC 23894:2023 — AI risklərinin idarə edilməsi

AI riski yalnız modelin səhv proqnoz verməsi deyil. Risk verilənlərin təmsilçilik səviyyəsindən, istifadə ssenarisindən, insanın modelə həddindən artıq etibar etməsindən, kibertəhlükələrdən, məxfilik pozuntusundan, təchizatçıdan və sistemin gözlənilməz dəyişməsindən yarana bilər. ISO/IEC 23894 AI risklərini təşkilatın ümumi risk idarəetmə prosesinə daxil etmək üçün rəhbərlik verir.

16.11.8. ISO/IEC TR 24027:2021 — qərəzliliyin aşkarlanması və azaldılması

Qərəzlilik yalnız alqoritmin kodunda yaranmır. Tarixi məlumatların qeyri-bərabərliyi, seçmə üsulu, etiketləyən şəxsin qərarı, ölçmə xətası, proksi dəyişənlər və tətbiq mühiti qərəz yarada bilər. ISO/IEC TR 24027 AI sistemlərinin həyat dövrü boyunca bias zəifliklərinin qiymətləndirilməsinə yönəlir.

Praktik audit nümunəsi

Fərz edək ki, universitetin akademik dəstək modeli iki qrup üzrə test edilib. A qrupunda TPR=0.90, B qrupunda TPR=0.75-dir. Fərq 0.15, yəni 15 faiz bəndidir. Bu fərq avtomatik olaraq ayrı-seçkilik sübutu deyil; nümunə ölçüsü, hədəf dəyişəninin keyfiyyəti, qrupların konteksti və səhvlərin nəticəsi araşdırılmalıdır.

TPR = TP / (TP + FN)

Audit zamanı TPR ilə yanaşı FPR, precision, calibration və müsbət qərar payı da nəzərdən keçirilə bilər. Hansı fairness meyarının seçilməsi tətbiq kontekstindən, qanuni tələblərdən və mümkün zərərdən asılıdır. Bütün fairness meyarlarının eyni vaxtda təmin olunması hər problem üçün mümkün olmaya bilər.

Vacib: həssas atributları sadəcə dataset-dən silmək bias problemini aradan qaldırmaya bilər. Poçt indeksi, məktəb, yaşayış yeri və digər proksi dəyişənlər həmin atributla əlaqəli qala bilər. ISO/IEC TR 24027:2021 rəsmi səhifəsi.

16.11.9. ISO/IEC 27001:2022 və ISO/IEC 27701:2025 — informasiya təhlükəsizliyi və məxfilik

AI sistemi verilənləri toplayır, saxlayır, emal edir və başqa sistemlərə ötürür. Buna görə AI etikasını informasiya təhlükəsizliyindən ayırmaq olmaz. ISO/IEC 27001:2022 təşkilatda informasiya təhlükəsizliyinin idarəetmə sistemini qurmaq üçün tələblər müəyyən edir. Məqsəd məlumatın məxfiliyini, bütövlüyünü və əlçatanlığını risk əsaslı şəkildə qorumaqdır.

ISO/IEC 27701:2025 isə fərdi identifikasiya edilə bilən məlumatların (PII) emalı üçün məxfilik məlumatlarının idarəetmə sistemini qurmağa yönəlir. 2025-ci il nəşri 2019-cu il nəşrini əvəz edib; buna görə yeni layihələrdə köhnə 2019 nəşrini cari nəşr kimi göstərmək olmaz.

16.11.12. Praktik hadisə təhlili: üç ssenari

Ssenari A — AI ilə tələbə qiymətləndirilməsi

Model tələbənin yazılı cavabına ilkin bal verir. Etik risk: dil üslubu və dialekt səbəbindən qərəz, yanlış qiymətləndirmə və tələbənin etiraz imkanının olmaması.

Düzgün yanaşma: rubrika ilə validasiya, müəllim tərəfindən yekun təsdiq, tələbəyə geribildirim, apellyasiya, fərqli dil qrupları üzrə test və məlumatların məxfiliyi.

Ssenari B — Universitet chatbotu

Chatbot tələbə müraciətlərinə cavab verir. Etik risk: yanlış normativ məlumat, uydurma tarix və sənəd, şəxsi məlumatın açıqlanması, prompt injection.

Düzgün yanaşma: təsdiqlənmiş bilik bazası, mənbə linkləri, qeyri-müəyyənlik bildirişi, səlahiyyət məhdudiyyəti, insan operatora ötürmə və logların qorunması.

Ssenari C — Tədqiqat məqaləsinin hazırlanması

Tədqiqatçı generativ AI-dan ədəbiyyat icmalı və kod üçün kömək alır. Etik risk: saxta istinad, plagiat, məxfi rəyçi materialının yüklənməsi və nəticələrin uydurulması.

Düzgün yanaşma: hər istinadı orijinal mənbədə yoxlamaq, AI istifadəsini jurnal qaydasına uyğun açıqlamaq, xam nəticələri təkrar hesablamaq və müəllif məsuliyyətini qorumaq.

16.11.13. Təşkilati AI Etik Kodeksi üçün nümunə müddəalar

Universitet və ya təşkilat öz daxili qaydasını hazırlayarkən aşağıdakı nümunə müddəaları uyğunlaşdıra bilər:

  1. AI sistemləri insan hüquqlarına, ləyaqətinə, bərabərliyə və qanunvericiliyə hörmət prinsipi ilə hazırlanmalı və istifadə edilməlidir.
  2. AI-dan istifadə məqsədi, istifadə sərhədləri, sistem sahibi və cavabdeh şəxslər əvvəlcədən müəyyən edilməlidir.
  3. AI tərəfindən yaradılan məzmun və ya avtomatlaşdırılmış qarşılıqlı əlaqə barədə istifadəçi zəruri hallarda məlumatlandırılmalıdır.
  4. Şəxsi, məxfi və xidməti məlumatlar yalnız qanuni əsas və təsdiqlənmiş təhlükəsiz mühit olduqda emal edilməlidir.
  5. Əhəmiyyətli insan nəticələrinə təsir edən AI qərarlarında mənalı insan nəzarəti və etiraz mexanizmi təmin edilməlidir.
  6. Modelin dəqiqliyi, ədalətliliyi, təhlükəsizliyi, izaholunması və dayanıqlılığı tətbiqdən əvvəl və istismar zamanı yoxlanılmalıdır.
  7. AI sistemində ciddi səhv, məlumat sızması və ya zərərli təsir aşkarlandıqda insident qeydə alınmalı, araşdırılmalı və zərurət olduqda sistem dayandırılmalıdır.
  8. Generativ AI ilə yaradılmış materialın müəlliflik, istinad, faktların yoxlanması və açıqlama qaydaları müəyyən edilməlidir.
Yekun fikir: etik AI yalnız etik kodeksin mövcudluğu ilə təmin olunmur. Kodeks idarəetmə sistemi, risk təhlili, təsir qiymətləndirilməsi, informasiya təhlükəsizliyi, məxfilik, qərəz auditi, insan nəzarəti və davamlı monitorinq ilə dəstəklənməlidir.

Praktiki tapşırıqlar

  1. Qərarın izahı: sadə Decision Tree və Random Forest modeli qurun. Eyni test müşahidəsi üçün ağac qaydasını və SHAP lokal izahını müqayisə edin.
  2. Feature Importance: permutation importance hesablayın. Ən vacib üç feature-i müəyyən edin və onların mümkün əlaqəliliyini təhlil edin.
  3. Qərəzlilik auditi: dataset-də mövcud və istifadəsi hüquqi baxımdan əsaslandırılmış qruplaşdırma atributları üzrə TPR, FPR və müsbət qərar paylarını müqayisə edin.
  4. Məxfilik təhlili: layihənizdə toplanan şəxsi məlumatları siyahıya alın; məqsəd, saxlanma müddəti, giriş rolu və qorunma tədbirlərini cədvəldə göstərin.
  5. Etibarlı AI sənədi: seçdiyiniz model üçün bir səhifəlik Model Card hazırlayın: məqsəd, nəzərdə tutulan istifadə, istifadə edilməməli ssenarilər, metriklər, qərəz riskləri və monitorinq.
  6. Milli Strategiya ilə uyğunlaşdırma: seçdiyiniz universitet AI layihəsini Strategiyanın 5.1.7, 5.1.8, 5.1.10, 5.1.11 və 5.1.12 məqsədləri ilə əlaqələndirin; hər məqsəd üçün ölçülə bilən tədbir və sübut müəyyən edin.
  7. ISO standartlarının tətbiq xəritəsi: layihəniz üçün ISO/IEC 42001, 23894, 42005, 27001 və 27701 standartlarının hansı proseslərdə istifadə oluna biləcəyini cədvəldə göstərin.
  8. Etik kodeks: ali təhsil müəssisəsi üçün generativ AI istifadəsinə dair 8–10 müddəadan ibarət daxili etik kodeks layihəsi hazırlayın.

Maşın öyrənməsi modelinin SHAP və ya Feature Importance vasitəsilə izah edilməsi və qərəzlilik təhlili

İşin məqsədi

Öyrədilmiş maşın öyrənməsi modelinin qərarlarına təsir edən xüsusiyyətləri müəyyənləşdirmək, lokal və ya qlobal izah yaratmaq, verilənlərdə mümkün qərəzliliyi araşdırmaq və nəticələri texniki hesabat formasında təqdim etmək.

İlkin verilənlər və etik tələblər

  • İstifadə üçün icazəli, şəxsi məlumatlardan təmizlənmiş və ya açıq dataset seçin.
  • Hədəf dəyişəni və feature-ləri aydın təsvir edin.
  • Həssas atributları yalnız qanuni və etik əsas olduqda fairness auditi üçün istifadə edin; onları ictimai hesabatda identifikasiyaedici formada açıqlamayın.
  • Train/test bölgüsündə data leakage riskini aradan qaldırın.

İcra mərhələləri

  1. Dataset-i yükləyin, ölçüləri, sinif balansını və çatışmayan dəyərləri təhlil edin.
  2. Baseline model qurun (məsələn, Decision Tree və ya Random Forest).
  3. Test dəstində Accuracy, Precision, Recall, F1 və uyğun olduqda ROC-AUC hesablayın.
  4. Feature Importance və ya SHAP vasitəsilə qlobal izah yaradın.
  5. Bir test nümunəsi üçün lokal izah (SHAP waterfall və ya LIME) hazırlayın.
  6. Mümkün qrup atributları üzrə performans və qərar paylarını müqayisə edin.
  7. Qərəz risklərini, metod məhdudiyyətlərini və azaldılma təkliflərini yazın.

from sklearn.inspection import permutation_importance
from sklearn.metrics import classification_report
import pandas as pd

# model əvvəlcədən fit olunub; X_test, y_test ayrılmış test dəstidir
pred = model.predict(X_test)
print(classification_report(y_test, pred))

result = permutation_importance(
    model, X_test, y_test,
    n_repeats=20,
    random_state=42,
    scoring="f1_macro"
)

importance = pd.DataFrame({
    "feature": X_test.columns,
    "importance_mean": result.importances_mean,
    "importance_std": result.importances_std
}).sort_values("importance_mean", ascending=False)

print(importance)

Fairness audit üçün qrup metrikləri — nümunə kod

from sklearn.metrics import confusion_matrix
import pandas as pd

def group_metrics(y_true, y_pred, group):
    rows = []
    for g in pd.Series(group).dropna().unique():
        mask = (pd.Series(group).values == g)
        tn, fp, fn, tp = confusion_matrix(
            pd.Series(y_true).values[mask],
            pd.Series(y_pred).values[mask],
            labels=[0, 1]
        ).ravel()
        tpr = tp / (tp + fn) if (tp + fn) else float("nan")
        fpr = fp / (fp + tn) if (fp + tn) else float("nan")
        positive_rate = (tp + fp) / mask.sum()
        rows.append({"group": g, "TPR": tpr, "FPR": fpr,
                     "positive_rate": positive_rate})
    return pd.DataFrame(rows)
