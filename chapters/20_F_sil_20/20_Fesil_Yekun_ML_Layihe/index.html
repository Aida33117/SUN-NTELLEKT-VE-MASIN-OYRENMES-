Bu fəsildən necə istifadə etməli?

Bu fəsil tələbəni yalnız hazır kodu icra etməyə deyil, müstəqil maşın öyrənməsi layihəsini planlaşdırmağa, əsaslandırmağa, qurmağa, yoxlamağa və təqdim etməyə hazırlayır. Layihənin mövzusu dəyişə bilər, lakin elmi iş axını ümumən eynidir: problem → məlumat → hazırlıq → model → qiymətləndirmə → prototip → hesabat.

Başlanğıc səviyyəsi

Python və əsas statistika biliklərini təkrarlayın. Kiçik, aydın və ölçülə bilən problem seçin.

Layihə düşüncəsi

Əvvəl tədqiqat sualı və uğur meyarı yazılır, sonra model seçilir. Əks ardıcıllıq layihəni məqsədsiz edir.

Elmi dürüstlük

Test datası təlimdə istifadə edilmir. Nəticələr, məhdudiyyətlər və uğursuz sınaqlar gizlədilmir.

Fəslin sonunda tələbə: real problemi ML tapşırığına çevirə, dataset kartı hazırlaya, məlumatı təmizləyə, baseline və ən azı iki model qura, uyğun metriklərlə qiymətləndirə, prototip yarada və elmi hesabatı müdafiə edə bilməlidir.

Yekun layihənin ümumi arxitekturası

Bu sxem xətti görünsə də, real layihə iterativdir. Test nəticəsi qənaətbəxş deyilsə, səbəb araşdırılır: məlumat keyfiyyəti, etiket, xüsusiyyət, model, hiperparametr və ya ölçmə üsulu yenidən nəzərdən keçirilir. Test dəstinə baxaraq təkrar-təkrar model seçmək test məlumatını dolayı yolla təlim prosesinə daxil edə bilər; model seçimi validation dəsti ilə aparılmalıdır.

20.1. Yekun layihənin məqsədi və tələbləri

Yekun layihənin məqsədi real problemin məlumat əsasında həll oluna biləcəyini göstərən, təkrarlana bilən və ölçülə bilən intellektual analiz sistemi hazırlamaqdır. “Süni intellektdən istifadə etmək” özü layihə məqsədi deyil. Məqsəd konkret olmalıdır: məsələn, “Tələbənin növbəti semestrdə akademik risk qrupuna düşmə ehtimalını əvvəlki semestrlərin göstəriciləri əsasında qiymətləndirmək”.

Problem seçimi üçün qərar meyarları

Hər meyarı 1–5 bal aralığında qiymətləndirin. Çəkili bal = meyar balı × çəki. Bu cədvəl qərarı strukturlaşdırır, lakin elmi sübutu əvəz etmir.

Problem bəyanatı şablonu: “[İstifadəçi/qurum] hazırda [problemlə] qarşılaşır. Bu layihənin məqsədi [məlumat mənbələri] əsasında [hədəf dəyişəni] proqnozlaşdırmaq/təsnif etmək və nəticəni [istifadə ssenarisi] üçün təqdim etməkdir. Uğur [metrik] və [praktiki meyar] ilə qiymətləndiriləcək.”

20.4. Verilənlərin təmizlənməsi və hazırlanması

Model məlumatın keyfiyyətindən asılıdır. İlk addım məlumatı anlamaqdır, dərhal bütün boş xanaları doldurmaq deyil. Missing values, dublikatlar, səhv tiplər, qeyri-mümkün qiymətlər, outlier-lər, etiket uyğunsuzluğu və məlumat sızması yoxlanılır.

İlkin yoxlama ardıcıllığı

  1. Faylın ölçüsü, sütun adları və tipləri.
  2. Boş dəyərlərin sayı və faizi.
  3. Dublikat müşahidələr.
  4. Kateqoriyaların yazılış uyğunsuzluğu.
  5. Hədəf paylanması və sinif balansı.
  6. Outlier və məntiqsiz dəyərlər.
  7. Hədəfi birbaşa və ya dolayı açıqlayan sütunlar (leakage).
df.isna().sum().sort_values(ascending=False)
df.duplicated().sum()

from sklearn.model_selection import train_test_split
X = df.drop(columns=["target"])
y = df["target"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, random_state=42,

Vacib qayda: imputasiya, scaling və encoding kimi parametrlər yalnız train hissəsində öyrənilməlidir. Bunun üçün Pipeline və ColumnTransformer istifadə edilir. Bütün datasetdə əvvəlcədən StandardScaler fit etmək test məlumatının statistik məlumatını təlimə sızdırır.

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer

numeric_pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler())
])
categorical_pipe = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore"))
])
preprocess = ColumnTransformer([
    ("num", numeric_pipe, numeric_cols),
    ("cat", categorical_pipe, categorical_cols)
])
Data leakage nümunəsi: tələbənin semestr sonunda yaranan yekun nəticəsini proqnozlaşdırarkən yekun qiyməti hesablayan sütunu girişə daxil etmək modelə cavabı əvvəlcədən verməkdir. Belə model yüksək metrik göstərə bilər, amma real istifadədə yararsızdır.

20.5. Model və alqoritmin seçilməsi

Alqoritm hədəfin növünə, dataset ölçüsünə, interpretasiya tələbinə və səhvin nəticəsinə görə seçilir. Başlanğıcda mürəkkəb neyron şəbəkəsi qurmaq məcburi deyil. Sadə baseline müqayisə nöqtəsi yaradır.

TapşırıqBaselineMüqayisə modelləriMetrik
Binary classificationDummyClassifierLogistic Regression, Random Forest, XGBoostRecall, Precision, F1, ROC-AUC / PR-AUC
RegressionDummyRegressorLinear/Ridge, Random Forest, Gradient BoostingMAE, RMSE, R²
ClusteringSadə K-Means baselineHierarchical, DBSCANSilhouette, Davies-Bouldin; domen yoxlaması
Time seriesNaive last-valueARIMA, tree-based lag features, LSTMMAE, RMSE, MASE

Model seçimi üçün suallar: nəticə izah edilməlidirmi? Siniflər balanslıdırmı? Məlumat azdırmı? Xəta hansı istiqamətdə daha bahalıdır? Model real vaxtda işləməlidirmi? Hesablama resursu varmı?

Baseline zəif görünə bilər, amma onun əsas rolu mürəkkəb modelin həqiqətən əlavə dəyər yaradıb-yaratmadığını göstərməkdir. Mürəkkəb model baseline-dan yaxşı deyilsə, daha sadə model seçmək əsaslandırıla bilər.

20.6. Modelin qurulması və öyrədilməsi

Modelin öyrədilməsi zamanı alqoritm train datasında parametrləri öyrənir. Validation dəsti hiperparametr seçmək, early stopping və model müqayisəsi üçün istifadə olunur. Test dəsti isə yekun, mümkün qədər bir dəfəlik qiymətləndirmə üçündür.

70/15/15 və ya 80/10/10 kimi bölgülər də istifadə oluna bilər. Dəqiq nisbət datasetin ölçüsü və strukturundan asılıdır; zaman sıralarında xronoloji bölmə seçilir.

from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

model = Pipeline([
    ("prep", preprocess),
    ("clf", LogisticRegression(max_iter=1000,
                               class_weight="balanced"))
])
model.fit(X_train, y_train)
pred = model.predict(X_test)
print(classification_report(y_test, pred))

Random seed təcrübənin təkrarlana bilməsinə kömək edir, lakin bütün kitabxana və GPU mühitlərində tam deterministik nəticəyə zəmanət vermir. Kitabxana versiyalarını, seed-i, hardware-i və parametrləri qeyd edin.

20.7. Modelin qiymətləndirilməsi

Qiymətləndirmə metrikləri tapşırığın məqsədinə uyğun seçilir. Classification üçün confusion matrix-də TP, TN, FP, FN sayılır. Precision yanlış alarmın, Recall isə real müsbətlərin nə qədərinin tapıldığını göstərir. Regression-da MAE orta mütləq səhv, RMSE böyük səhvləri daha çox cəzalandıran kvadratik ölçü, R² isə modelin variasiyanı nə qədər izah etdiyini göstərən göstəricidir.

İnteraktiv classification metrik kalkulyatoru

Modelin nəticəsini yalnız bir rəqəmlə təqdim etməyin. Confusion matrix, siniflər üzrə precision/recall, ROC və PR əyrisi, kalibrlənmə, threshold seçimi və səhv nümunələrinin təhlili daha dolğun mənzərə yaradır. Nəticənin qeyri-müəyyənliyi üçün cross-validation və ya bootstrap intervalı nəzərdən keçirilə bilər.

20.8. Nəticələrin müqayisəli təhlili

Müqayisə ədalətli olmalıdır: modellər eyni train/test bölgüsündə, eyni preprocessing protokolunda və eyni metriklə qiymətləndirilməlidir. Hiperparametr axtarışının büdcəsi də qeyd edilməlidir. Ən yüksək rəqəmi seçməklə kifayətlənməyin; modelin sabitliyi, interpretasiyası, sürəti, yaddaş sərfi və səhvlərinin növü də vacibdir.

Cədvəldəki rəqəmlər izah məqsədli nümunədir, real eksperiment nəticəsi deyil. Tələbə öz datasetində ölçdüyü nəticələri yazmalıdır.

Statistik fərq iddiası irəli sürərkən təkcə 0.01 fərqi “əhəmiyyətli” adlandırmaq olmaz. Təkrar cross-validation nəticələri, etibar intervalı və uyğun statistik test seçimi nəzərdən keçirilməlidir. Eyni test nümunələri üzərində müqayisədə paired yanaşmalar üstün ola bilər.

20.9. İntellektual sistemin prototipinin hazırlanması

Prototip modelin laboratoriyadan istifadəçi ssenarisinə keçididir. Prototip istifadəçidən giriş qəbul edir, eyni preprocessing-i tətbiq edir, modeldən nəticə alır və nəticəni başa düşülən formada göstərir. Prototip elmi nəticəni nümayiş etdirməlidir, lakin klinik, maliyyə və ya digər yüksək riskli qərarları insan yoxlaması olmadan avtomatlaşdırmamalıdır.

Sadə sistem arxitekturası

Başlanğıc üçün Streamlit rahat seçimdir. Model və preprocessing pipeline-ı fayla saxlayın; tətbiqdə təlimi təkrar etməyin, yalnız yüklənmiş modeli çağırın. İstifadəçi girişinin validasiyası, səhv mesajları, model versiyası və audit qeydi əlavə edin.

# app.py — minimal Streamlit prototip skeleti
import streamlit as st
import joblib
import pandas as pd

st.title("İntellektual analiz sistemi")
model = joblib.load("ml_pipeline.joblib")

age = st.number_input("Yaş", 16, 100, 22)
attendance = st.slider("Davamiyyət (%)", 0, 100, 80)
avg_grade = st.number_input("Orta bal", 0.0, 100.0, 70.0)

if st.button("Təhlil et"):
    row = pd.DataFrame([{
        "age": age,
        "attendance": attendance,
        "avg_grade": avg_grade
    }])
    prediction = model.predict(row)[0]
    st.success(f"Modelin proqnozu: {prediction}")
    st.caption("Bu prototip qərar dəstəyi üçündür; yekun qərarı məsul şəxs verir.")

Bu kod yalnız nümunə skeletidir: sütun adları və model faylı sizin real layihənizə uyğun olmalıdır. Təlim zamanı istifadə edilən sütun sırası və preprocessing tətbiqdə də eyni olmalıdır.

Laboratoriya işi №20: Seçilmiş real problem üzrə tam maşın öyrənməsi layihəsinin hazırlanması və təqdim edilməsi

Laboratoriyanın məqsədi: tələbənin seçdiyi real problem üzrə bütün ML həyat dövrünü icra etməsi və işlək prototip təqdim etməsi.

İcra mərhələləri

1-ci həftə — Problem və hipotez. Problem bəyanatı, tədqiqat sualı, məqsəd, hipotez və uğur meyarı yazılır.
2-ci həftə — Dataset. Məlumat mənbəyi, lisenziya, dəyişənlər, hədəf və Dataset Card hazırlanır.
3-cü həftə — EDA və təmizləmə. Boş dəyərlər, dublikat, paylanma, outlier, leakage və sinif balansı araşdırılır.
4-cü həftə — Baseline. Sadə baseline qurulur, uyğun metrik seçilir və ilk nəticə qeyd edilir.
5-ci həftə — Model müqayisəsi. Ən azı iki model qurulur, validation ilə hiperparametrlər seçilir.
6-cı həftə — Test və səhv təhlili. Test dəsti bir dəfə yekun qiymətləndirmə üçün istifadə olunur; səhvlər araşdırılır.
7-ci həftə — Prototip. Streamlit və ya başqa interfeys qurulur; model versiyası və giriş yoxlaması əlavə edilir.
8-ci həftə — Hesabat və müdafiə. Hesabat, təqdimat, demo və təkrarlana bilən fayllar tamamlanır.

Praktiki tapşırıqlar

  1. Öz ixtisasınıza uyğun üç real problem seçin və qərar meyarları ilə ən uyğununu əsaslandırın.
  2. Seçilmiş problem üçün bir cümləlik problem bəyanatı, tədqiqat sualı və yoxlanıla bilən hipotez yazın.
  3. Uyğun dataset tapın və Dataset Card hazırlayın.
  4. Datasetin ölçüsünü, tiplərini, boş dəyərlərini və hədəf paylanmasını təhlil edin.
  5. Train/validation/test bölgüsünü seçin və seçiminizi əsaslandırın.
  6. Preprocessing Pipeline qurun və data leakage riskini izah edin.
  7. Baseline və ən azı iki ML modelini eyni protokolla müqayisə edin.
  8. Classification və regression üçün uyğun metrikləri seçin və nəticələri şərh edin.
  9. Model səhvlərindən 10 nümunə seçərək error analysis aparın.
  10. Modeli istifadəçiyə təqdim edən Streamlit prototipi hazırlayın.
  11. Layihə hesabatını bu fəsildə verilən struktura uyğun yazın.
  12. 5–7 dəqiqəlik müdafiə təqdimatı və canlı demo hazırlayın.
